R-1648 Windows AppContainer Provider 施工。三面红→归因→修正→四面全绿全过程。

## 归因链（二分序列，全留痕）

环境变量逐一面排除（同一测试进程内对照）：

| 嫌疑面 | 实验 | 结果 |
|---|---|---|
| 机器态/环境劣化 | 同进程跑 Debug2（spike 保真复刻） | 全绿 err=nil——环境没变 |
| profile 同名重建损坏 | 纳秒唯一名（已修） | 仍红——非此因 |
| inherit 句柄/CWD/SUSPENDED/入 Job | Debug2 (g) 全保真 | 绿——非此因 |

| workspace/tmpDir ACE 授予 | Debug2 (c)/(d) 授予后 spawn | 绿——非此因 |
| **profile 名长度（46 vs 34）** | Debug3 长度阶梯 | **全档 create 败——但长度无关** |
| **create 第三参数 pszDescription** | Debug3 vs Debug2 直调对照 | **根因实锤** |

## 根因①：pszDescription=NULL → 幻影 profile

`CreateAppContainerProfile` 六参数中第三参数（pszDescription）**不可为 NULL**：

- Debug2 直调传 `namePtr`（非 NULL）→ HRESULT=0x00000000 ✅
- provider `winACCreateProfile` 传 `0` → **HRESULT=0x80070057（E_INVALIDARG）** ❌

失败被 derive 兜底吞掉：`DeriveAppContainerSidFromAppContainerName` 是纯名称哈希、
**恒成功、不要求 profile 存在**——产出语义完好（S-1-15-2-* 形态）但无实体的
「幻影 profile SID」。SECURITY_CAPABILITIES 引用幻影 profile → CreateProcess 报
`The system cannot find the file specified`（与「同名重建永久损坏」同失败形态——
内核找不到 profile 实体）。

Debug3 原始输出（长度阶梯 34/46/50/64 全败=长度无关实锤）：
```
len=34 create 败 HRESULT=0x80070057 —— derive 兜底=幻影 profile
len=34 derive 成功但 spawn: The system cannot find the file specified.（幻影 profile 实锤）
len=46 create 败 HRESULT=0x80070057（同上）……len=50/64 同
```

**修正**（provider_winac_windows.go winACCreateProfile）：
1. 第三参数传 `namePtr`（非 NULL）；
2. 兜底语义硬化——仅 `HRESULT=0x800700B7`（ERROR_ALREADY_EXISTS）准许 derive
   兜底，其余失败立即报错带真实 HRESULT（幻影 profile 构造性不可能再现）。

## 根因②：Execute 全程持锁 → Release 绞杀死锁

根因①修后 Lifecycle 转红新形态：测试整跑 60.21s=sleeper 睡满全程——
`Execute` 持 `h.mu` 全程（WaitForSingleObject 60s），`Release` 首句 `h.mu.Lock()`
阻塞到 sleeper 自然结束，KILL_ON_JOB_CLOSE 绞杀窗口完全错过。

**修正**：锁粒度拆分——`h.mu` 只护 state（校验/翻转瞬时完成）；Execute/Precheck
锁内 `wg.Add(1)` 后解锁执行；Release 锁外 `CloseHandle(job)`（先绞杀）→
`wg.Wait()`（等在飞收尾）→收 ACE/删 profile/FreeSid（防 use-after-free）。
HandleGuard 无自带锁（纯前置校验委托 spi.go:146-238）——死锁确在 provider 层。
