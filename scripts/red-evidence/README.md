# red-evidence 存证契约（R-1632——会议 #252）

本目录存 **R-571 测试先行纪律的 RED→GREEN 转换证据**。

## 为什么入库（而非 CI artifacts）

业界惯例（GitHub Actions/GitLab CI）：测试**运行结果**=CI artifacts 不入库——因为它们是**可再生输出**，每次运行重新生成，GitHub artifacts 默认 90 天过期也无妨。

red-evidence 不是那个物种：**先红状态转瞬即逝**——代码一转绿，RED 就永远无法复现（除非翻 git 历史重演）。不可再生的存续证据必须持久且防篡改，git 历史正好两者都给。因此本目录是 scripts/ 白名单的合法内容（GIT-RULES 规则 5 的"审计记录"排除项=运行时审计导出日志，非测试留痕）。

## 存证契约

1. **命名**：`YYYY-MM-DD-<专项编号>-red|green.txt`（如 `2026-08-27-s245-01-red.txt`）；同一专项的 red 与 green 成对存在。
2. **内容最小集**：执行的命令 + 关键输出摘录 + 当时 commit hash + 日期。
3. **只存转换证据**：一次 RED→GREEN 一事一档。例行测试日志/覆盖率报告/构建输出**禁止入库**（属可再生输出，归 CI artifacts）。
4. **不可修改**：存证文件一旦提交不得改写（历史修正=新文件+注记引用旧档）。
